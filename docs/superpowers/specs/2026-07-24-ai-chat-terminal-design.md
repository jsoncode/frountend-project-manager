# AI 对话窗口与终端投喂 — 设计规格

日期：2026-07-24  
状态：已确认（待实现计划）

## 背景与目标

在 FPM 终端中支持选区右键操作，并将选中日志「投喂」到独立 AI 对话 Webview 窗口，提供类主流 Chat 产品的对话、历史与多模型配置能力。

## 决策摘要

| 项 | 选择 |
|----|------|
| 交付范围 | 终端右键 + 完整 AI 窗口一次落地 |
| API | OpenAI 兼容为主（`/v1/chat/completions` + SSE），接口层预留扩展 |
| 底部能力 | 开关型：流式 / 思考 / 编程（可多选） |
| 终端投喂 | 选区作为「上下文附件」，不自动发送 |
| 架构 | 独立 WebviewWindow + 本地持久化 + Rust 代理请求（方案 A） |

## 1. 整体架构与数据模型

### 1.1 窗口与路由

- **主窗口**：现有 FPM；终端右键菜单在此实现。
- **AI 窗口**：Tauri `WebviewWindow`（label 如 `ai-chat`），加载同一前端构建，通过 hash/query（如 `/#/ai`）渲染独立根组件 `AiApp`，不复用主 `App` 布局。
- **投喂**：主窗口打开或聚焦 AI 窗口，经事件或启动参数传入选中文本，作为当前轮次的上下文附件。

### 1.2 请求链路

```
AI 前端 → Tauri command（如 chat_stream）→ Rust HTTP 客户端
       → OpenAI 兼容 /v1/chat/completions（SSE）
       → 事件流回前端增量渲染
```

- Token 仅存本地配置，由 Rust 读取并写入 `Authorization`。
- 前端不落盘、不打印明文 token。

### 1.3 本地数据（应用配置目录）

**AiModel**

- `id`, `remark`, `baseUrl`, `modelName`, `token`, `type`（`text` | `image` | `audio` | `video` | `multimodal`）, `active`（是否启用）

**AiConversation**

- `id`, `title`, `modelId?`, `createdAt`, `updatedAt`

**AiMessage**

- `id`, `conversationId`, `role`（`user` | `assistant` | `system`）, `content`, `reasoning?`, `attachments?`, `createdAt`

**AiAttachment**

- `kind`: `terminal-selection`, `text`, `createdAt`

会话列表按 `updatedAt` 分组：**最近一个月** / **更早**。

### 1.4 首版能力边界

- 对话：文本流式；可选思考块展示；可选编程系统提示。
- 模型类型：设置 UI 支持全部类型；**实际请求首版仅文本路径**。非文本类型可选中，发送时提示暂不支持（或发送按钮灰显）。

## 2. UI 布局与交互

视觉沿用现有 FPM 深色主题（cyan 强调色、面板边框、小号控件）。

### 2.1 布局

```
┌──────────┬─────────────────────────────┐
│ 历史侧栏  │  顶栏：模型下拉 │ 设置        │
│ 最近一月  ├─────────────────────────────┤
│ · 对话A   │                             │
│ · 对话B   │      消息流（可滚动）          │
│ 更早      │                             │
│ · …      ├─────────────────────────────┤
│ [+ 新对话]│ 上下文附件条（可移除）         │
│          │ [流式][思考][编程]  输入框 [发送]│
└──────────┴─────────────────────────────┘
```

### 2.2 左侧历史

- 分组：最近一个月 / 更早（按 `updatedAt`）。
- 每项：标题（单击选中；双击或「重命名」修改）；删除需确认。
- 「新对话」：立即创建空会话。

### 2.3 顶栏与设置

- 左：当前启用模型下拉（仅 `active`；显示备注优先）。
- 右：设置打开**窗口内 Modal**（不再开 Webview）：
  - 模型 CRUD：备注、接口地址、模型名称、token（默认遮罩）、类型、启用开关。
  - 可启用多个；下拉里均可选；**默认选中最近使用的启用模型**。

### 2.4 消息区与底部

- User / Assistant 气泡；思考开启时 Assistant 可折叠「思考」块。
- 流式逐字追加；生成中提供「停止」，禁止并发发送。
- 开关：流式（默认开）、思考、编程（可多选）。
- 终端投喂显示附件芯片「终端选区」，可移除。
- 发送组包：编程系统提示（若开）+ 历史消息 + 附件上下文 + 用户输入。
  - **编程开**：在请求前插入固定 system（偏代码解释/修复，中文回复）。
  - **思考开**：请求仍走 chat completions；若响应含 `reasoning_content` / `reasoning` 则写入消息的 `reasoning` 并折叠展示，否则不强制厂商专有字段。
  - **附件**：拼入本轮 user 消息，格式为：

    ```
    [终端选区]
    ```
    {attachment text}
    ```

    ---
    {用户输入}
    ```

  - **流式关**：同一 endpoint，非 SSE 整包解析。

### 2.5 终端右键（主窗口）

| 选区 | 菜单 |
|------|------|
| 有选区 | 复制、全选、投喂 AI |
| 无选区 | 全选可用；复制与投喂禁用 |

## 3. 错误处理与边界

- 无启用模型：禁用发送，提示先配置。
- 非文本模型：发送时提示暂不支持。
- 网络/401/超时：消息区错误条，保留已输出；可重试最后一轮。
- 流式中途失败：标记 assistant 消息不完整。
- 停止：取消 Rust 侧 SSE 读取，冻结已输出。
- 附件超长（如 >100KB）：截断并提示。
- AI 窗口已打开再投喂：**聚焦已有窗口**，**替换**当前未发送附件，不新开窗口。
- 关闭 AI 窗口：已落盘会话下次恢复；进行中的流式请求取消。

## 4. 测试要点

- 终端右键：有/无选区菜单状态；复制与选区一致；全选覆盖缓冲。
- 投喂：打开/聚焦窗口、附件展示与移除、发送是否含附件。
- 模型 CRUD、启用过滤、默认模型。
- 流式开/关；思考/编程对请求体的影响。
- 历史分组边界、重命名、删除。
- 无模型、错误 API、停止生成。

## 5. 非目标（首版不做）

- Claude / 非 OpenAI 协议的完整原生适配（仅预留扩展点）。
- 图像/音频/视频的实际上传与多模态请求体。
- 云端同步会话、账号体系、计费。
- 主窗口内嵌 AI 侧栏（明确采用独立 Webview）。

## 6. 实现落点（指导性）

- 前端：`AiApp` 路由入口；`ai/*` 组件与 store；`XtermSession` 右键菜单。
- Rust：`ai` 模块（模型/会话持久化、`chat_stream`、开窗）；权限配置。
- 配置：与现有 `AppConfig` 分离的 `ai-config` / `ai-chats` 文件，避免主配置膨胀。
